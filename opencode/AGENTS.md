When a project's rules change, update its AGENTS.md — extend existing sections where possible, prune what becomes stale, and don't append narration of routine code changes (commit messages cover that).

Never `git commit` or `git push` on your own initiative — in any repo, including when a project's workflow (CI-on-merge, PR flow) makes it convenient. Prepare the changes, leave the branch/working tree ready, and tell the user it's ready; only commit or push when they explicitly ask in that request. Project conventions about commit style apply only once the user has asked for the commit.

## DRY — "Every piece of knowledge must have a single, unambiguous, authoritative representation within a system" (Hunt & Thomas, The Pragmatic Programmer)

Apply DRY broadly — not just code (dedupe via functions/abstractions) but database schemas, test plans, build systems, and documentation too. Prefer abstractions that are unlikely to change, or normalize data so redundancy never exists. Done right, changing one element never requires touching logically unrelated elements, and related elements change predictably and stay in sync. When you find yourself copy-pasting knowledge across files, extract it to its single authoritative source instead.

Try to refrain from using insider lingo when talking about finances.

## opencode-sudo plugin

`plugins/opencode-sudo` rewrites command-position `sudo` in **agent-typed** shell commands to `pkexec --disable-internal-agent sudo -n` (policy `ask` default; live toggle file `~/.config/opencode/sudo-policy`, env `OPENCODE_SUDO_POLICY`, `/sudo on|ask|off`). Three consequences: (1) agent sudo works only while polkit authorizes — with no polkit agent running it fails fast with "a password is required" once the auth window expires; (2) it never populates sudo's timestamp, so `sudo -n` inside *scripts* (invisible to the rewrite) fails — standalone elevated scripts need `/etc/sudoers.d` NOPASSWD rules instead; (3) `sudo -n -l` / `sudo -n id` output reflects **root** (via pkexec), not the invoking user — don't misread it as a root shell context. To bypass the rewrite in agent-typed commands, call the full path `/usr/bin/sudo`. dan's sudoers otherwise requires a password (no blanket NOPASSWD).

## FreeTube — IPv4-only netns (freetube4)

FreeTube lives at `~/.local/opt/freetube` (manually extracted deb; update via `~/.local/bin/freetube-update` which swaps dirs and keeps one `.prev` generation), launched through `~/.local/bin/freetube` → `sudo -n /usr/local/sbin/freetube4-launch` (fixed root helper that enters netns `freetube4`, injects display env, drops to dan via setpriv) → app with `--ozone-platform=x11`. Why: YouTube rate-limits/bans IPv6 addresses for logged-out API clients (FreeTubeApp/FreeTube#7906); residential IPv4 is unaffected, so the netns (veth 10.77.0.1/30↔10.77.0.2/30, NAT out `eno1`, IPv6 sysctls disabled inside) scopes the fix to FreeTube only. Persistence: `/etc/systemd/system/freetube4-netns.service` (enabled) runs the idempotent `/usr/local/sbin/freetube4-netns.sh up` at boot; the wrapper auto-creates if missing. Elevation: `/etc/sudoers.d/freetube-netns` grants dan NOPASSWD for exactly those two scripts — the sudoers route is required because plugin elevation (above) can't reach runtime sudo inside scripts. Settings: `~/.config/FreeTube/settings.db` is **nedb** (newline-delimited JSON, `{"_id":…,"value":…}`, last doc wins) — edit only with the app closed; Tor proxy disabled (`useProxy:false` — Tor exits get banned by YouTube almost immediately), RSS subscription fetch (`useRss:true`) and API fallback (`backendFallback:true`) enabled (backup at `settings.db.bak-20261118`). Canonical copies of all seven pieces (wrapper, updater, desktop file, launch helper, netns script, system unit, sudoers rule) live in `~/dotfiles/freetube/` and are installed by `./install` — dotbot links the user-level trio into `~/.local/bin` + `~/.local/share/applications`, one sudo shell step does the `/usr/local/sbin` + `/etc` installs, `visudo` check, and `systemctl enable --now`. The updater handles a fresh machine (no existing `~/.local/opt/freetube`); user data (`~/.config/FreeTube/*.db`) migrates by manual copy.

## Vocalinux — Pa_Terminate wedge hotfix

Pacman package `vocalinux 0.18.6-1` (upstream VocaHQ/vocalinux). Known failure mode (hit 2026-11-18): stop-time `PyAudio.terminate()` → `Pa_Terminate` blocks forever inside a wedged pipewire-jack client (`jack_deactivate` → `pthread_cond_wait` in libjack), so the capture thread never exits and every dictation start logs "Cannot start recognition while capture is still stopping" — permanently. Symptom in logs: "Capture is still alive; suppressing stop cue" on one stop, then all later starts refused. Diagnose live with `~/.local/bin/py-spy dump --pid <pid> --native` (py-spy installed 2026-11-18; needs elevation: prefix `pkexec --disable-internal-agent env "PATH=$HOME/.local/bin:/usr/bin"`). Hotfix applied to `/usr/lib/python3.14/site-packages/vocalinux/audio/capture.py`: `_terminate_pyaudio_bounded()` runs terminate on a daemon helper with a 3 s deadline and abandons a wedged instance instead of hanging capture teardown. **Pacman-owned file — any vocalinux package rebuild wipes the patch; reapply by regenerating it** (exact old/new blocks preserved in the session that created it; conceptually: bound `self.audio.terminate()` in `PortAudioCaptureSource.close()`). Check upstream before reapplying — reported upstream as VocaHQ/vocalinux#1072 (2026-11-18, includes the py-spy native stack and the patch); if fixed upstream in a release, prefer the package upgrade. Runtime is a plain process, not a user unit (after restarts via `systemd-run --user --unit=vocalinux-hotfix`, kill that unit first to avoid duplicate tray instances).
