When a project's rules change, update its AGENTS.md — extend existing sections where possible, prune what becomes stale, and don't append narration of routine code changes (commit messages cover that).

Never `git commit` or `git push` on your own initiative — in any repo, including when a project's workflow (CI-on-merge, PR flow) makes it convenient. Prepare the changes, leave the branch/working tree ready, and tell the user it's ready; only commit or push when they explicitly ask in that request. Project conventions about commit style apply only once the user has asked for the commit.

## DRY — "Every piece of knowledge must have a single, unambiguous, authoritative representation within a system" (Hunt & Thomas, The Pragmatic Programmer)

Apply DRY broadly — not just code (dedupe via functions/abstractions) but database schemas, test plans, build systems, and documentation too. Prefer abstractions that are unlikely to change, or normalize data so redundancy never exists. Done right, changing one element never requires touching logically unrelated elements, and related elements change predictably and stay in sync. When you find yourself copy-pasting knowledge across files, extract it to its single authoritative source instead.

Try to refrain from using insider lingo when talking about finances.

## Browser automation — agent-browser

Config lives in `~/.agent-browser/config.json` (symlink to `~/dotfiles/agent-browser/config.json`): hardware-GPU launch args (`--use-angle=vulkan,--enable-features=Vulkan` — WebGL renders on the RTX 4070 Ti instead of SwiftShader-on-CPU, which pegs every core at ~1300%) and a 15-minute idle timeout that auto-closes the headless browser. It is also mounted as an opencode MCP server (`core,network` tool profiles, in opencode.jsonc) — prefer those typed tools; the CLI still works for everything. There is no config-level viewport key: pin per session with `agent-browser set viewport 1440 900` (the headless default height clipped nav labels and mis-mapped clicks). Still run `agent-browser close --all` when done with a browser task. If a `chrome --type=gpu-process` under `~/.agent-browser/browsers/` ever spins up CPU again, it means the config was bypassed/overridden — check the config first, don't just pkill. Kill scoped with `pkill -f '.agent-browser/browsers/chrome'`; never blanket `pkill chrome` (Steam and other apps embed Chrome). Do not attach to the user's running Helium browser (`--connect`/`--auto-connect`) — that hijacks their tabs and personal session.

## EverOS memory server

Backs the `ever-opencode` npm plugin — automatic per-turn memory capture + recall for every OpenCode session. Runs as the `everos.service` systemd **user** unit: enabled + linger (boots with the OS), unit file at `~/dotfiles/systemd/everos.service` (symlinked into `~/.config/systemd/user/`). Secrets live in `~/.config/everos/server.env` (chmod 600, **not** in the repo — sanitized template at `~/dotfiles/everos/server.env.example`); LLM extraction + retrieval decider run on DeepSeek (`deepseek-chat`, key from `~/.zsh_api_keys`) and embeddings on DashScope intl (`text-embedding-v4`, dims 1024, same key file) — deliberately **not** the GLM coding endpoint, whose plan-wide rate limit (`429 code 1302`) the plugin's per-turn traffic exhausts. Rerank is unconfigured (DeepInfra needs a signup; DashScope intl lacks `gte-rerank-v2`) — search runs RRF-only, fine. Server configs `~/.everos/{everos,ome}.toml` are symlinked to `~/dotfiles/everos/`. Memory store: `~/.everos/opencode/<project>/users/dan/` — plain markdown episodes. Ops: `journalctl --user -u everos`; restart `systemctl --user restart everos`; full memory reset `rm -rf ~/.everos/opencode && systemctl --user restart everos`. `everos cascade rebuild` requires the unit stopped and does **not** read server.env (systemd-only) — export `EVEROS_EMBEDDING__API_KEY` inline or it re-indexes keyword-only. **Local site-packages patch** `~/dotfiles/everos/everalgo-json-repair.patch` (everos 1.5.1): adds `_loads_lenient` trailing-comma repair to everalgo's four extractors (episode/profile/atomic_fact/foresight) — DeepSeek emits lax JSON and strict `json.loads` failed intermittently, 500-ing `/flush`. Reapply after `uv tool upgrade everos`: `patch -p1 -d ~/.local/share/uv/tools/everos/lib/python3.12/site-packages < ~/dotfiles/everos/everalgo-json-repair.patch` (upstream repo: EverMind-AI/EverOS — filed as issue #564, draft at `~/dotfiles/everos/issue-draft.md`). Never run a manual `everos server start` while the unit is active — it holds the index lock. Sessions degraded by a server outage stay degraded until reopened; new sessions re-arm automatically.
